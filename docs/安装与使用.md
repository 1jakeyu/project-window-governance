# 安装与使用

这是 `project-window-governance`（项目窗口与任务治理）的安装与恢复补充说明。优先使用 [README 的自动安装入口](../README.md#自动安装)，由当前智能体获取并安装，无需用户先手动下载。它来自安装记录标识为 `2026.10.13.1` 的安装快照；历史正式维护源尚未确认；当前独立仓库维护公开候选。本候选新增模型派发指引，不能据此认定它是所有历史分支的最新正式发布版。

本包帮助整理指定项目的聊天职责、任务、验证证据和交接。安装本身不会建立聊天、发送消息、归档、改名、授予项目写权限，也不会把旧设备上的批准转移到新设备。它不提供常驻运行、跨设备执行或可选中央服务接通。两个辅助脚本本身不联网，不要求 API Key；智能体的平台工具能力另行核对。

## 平台与自动安装

支持本地 Skill 的平台先核对实际格式与发现目录，再从 README 指定版本目录自动安装。Codex 可使用内置 `$skill-installer`；其他智能体使用其已有安装能力，不套用 Codex 命令。缺少安装工具或本地写权限时明确报告，不能声称已经安装。以下 Windows / Mac 步骤是需要手动处理时的备用方法。

## Codex：先确定目标位置

2026-11-09 已核对的[官方技能说明](https://learn.chatgpt.com/docs/build-skills)：个人目录为 `~/.agents/skills`，项目目录为 `.agents/skills`；支持 `$技能名` 调用。变更未出现可重启；实际配置可按技能绝对 `SKILL.md` 路径设 `enabled=false` 后重启停用。

`~` 表示当前用户的个人文件夹。Windows、Mac 和旧版 Codex 的实际发现位置可能不同：**先让目标 Codex 确认它实际读取的技能目录，再复制**。源设备使用自定义技能目录，其具体位置不适用于其他设备。不要修改全局 `CODEX_CLI_PATH` 来安装技能。

建议先在一个项目中试用；只有希望多个项目都能调用时才选择个人技能目录。项目安装与个人安装应避免留下两份同名技能，防止无法判断加载了哪份。

## Windows 手动安装

1. 在文件资源管理器中打开 ZIP 解压后的根目录，找到完整的 `project-window-governance` 文件夹。只安装技能子目录，不把仓库根的文档清单当成技能。
2. 打开目标 Codex 已确认的技能目录。个人目录通常可从资源管理器地址栏输入 `%USERPROFILE%`，再进入 `.agents` → `skills`；项目目录则从实际项目文件夹进入 `.agents` → `skills`。若目录不存在，先核实位置，再手动新建。
3. 检查里面是否已有 `project-window-governance`。已有时停止复制，按下面“同名处理”操作。
4. 没有同名时，将完整文件夹复制进去。保持 `adapters`、`references`、`scripts`、`templates` 等原有相对位置，不要只复制 `SKILL.md`。
5. 打开复制后的文件夹，应直接看到 `SKILL.md`。正确示例是 `<确认的技能目录>/project-window-governance/SKILL.md`，错误示例是 `.../project-window-governance/project-window-governance/SKILL.md`（多套了一层）。

## Mac 手动安装

1. 在 Finder 中打开 ZIP 解压后的根目录，找到完整的 `project-window-governance` 文件夹。
2. 按 `Command + Shift + G` 打开“前往文件夹”，输入目标 Codex 确认的目录，例如个人目录 `~/.agents/skills`；项目目录要从你选定的实际项目定位。
3. 缺少目录时先核实后手动新建；已有同名文件夹时停止复制，按下面规则处理。
4. 将整个 `project-window-governance` 文件夹复制进去，不选择“合并”。打开后应直接看到 `SKILL.md`，不能出现两层同名文件夹。

## 同名处理：先比较，再决定

已有安装不能盲目覆盖、合并或删掉。

1. 先记录旧安装的准确位置、版本或记录标识，使用包内提供的指纹清单比较文件。SHA-256 指纹是文件内容的识别值；相同表示内容相同，不能只凭文件名判断。若本包附有 SHA-256 清单，按清单给出的相对路径逐项核对，同时确认有没有清单外的现有文件。
2. 如果无法比较，或旧安装含本机修改，停止替换，让 Codex 在限定的两个文件夹内做只读比较，不扫描其他技能或个人目录。
3. 提出准确的替换计划：旧目录、新包目录、差异、备份位置、恢复步骤和验证方法。**用户明确批准具体计划后，才执行涉及旧文件的替换。**同名文件夹不合并。
4. 按获批计划，将旧文件夹完整复制到技能发现目录之外的明确备份位置；确认备份可读，再做获批替换。备份不能放回 `skills` 中，以免被当作另一份技能加载。
5. 替换后确认加载路径、文件指纹及一次只读调用；失败时停止写入，按获批恢复计划恢复旧安装。不自行删除备份。

首次安装只新增文件夹；替换、移动或删除已有文件，以及改配置，都必须有对应的具体授权。

## 第一次调用与验证

在目标智能体的项目聊天中使用该平台的技能调用方式；下面是 Codex 示例：

```text
$project-window-governance
请先只读确认：你是否发现这个技能、实际加载的 SKILL.md 绝对路径是什么、能读到哪些适配文件。不要修改任何文件或聊天。然后先核对当前平台、可用模型及其来源、思考深度和派发能力，再列出治理本项目需要的最少信息和正式跨聊天工具；没有实际调用验证的能力写“未验证”。
```

预期看到技能名称、真实加载位置和能力边界。若看不到技能，可重启 Codex 再试一次；若路径不对、出现两份同名或仍无法发现，停止安装变更，保留现状，让目标 Codex 检查它实际发现的目录。不要为此扫描整个用户目录或读取私有会话数据库。

接着使用 [提示词与试点.md](提示词与试点.md) 中的首次只读盘点提示词。只读验证通过后，再单独批准需要执行的具体写操作。

## Python 与两个离线工具

日常阅读技能、整理摘要和人工维护现有台账不要求 Python。只有使用 `scripts/scan_windows.py` 或 `scripts/tasks.py` 时才需要 Python。静态审查最低为 Python 3.9（任务脚本使用 `Path.is_relative_to`）；实际运行测试为 Windows Python 3.12.10，Python 3.9 与 Mac 实机尚未验证。两个辅助脚本只依赖 Python 标准库，不要求安装第三方包。先检查目标设备已有环境，安装或升级另行取得明确批准。

- `scan_windows.py`：整理正式工具或用户提供的最小窗口数据，不采集聊天。默认只输出结果；写文件必须另有授权。
- `tasks.py`：仅当项目选择了本技能任务卡格式且已授权写入时使用；显式指定项目已有任务卡目录，不自动建立第二套台账。创建草稿不等于批准执行；`--by-user` 仅记录真实发生过的用户决定。

命令参数和字段以 `SKILL.md`、`adapters/codex.md`、`references/receipt-format.md` 为准。缺少验证写 `unverified`；检查通过不等于用户验收或项目完成。

每轮使用稳定的 `receipt_id`（回执编号），同次重试复用编号和内容。写入中断使用 `recover --receipt-id <原编号>` 补完原操作；发生冲突就停止该任务的写入并报告实际差异，不删恢复日志、不换编号掩盖失败。跨设备共享目录仍须单一写入主责。

本包不包含外部上报脚本，也不假定本地回执兼容任意接收端。需要对接时，先读实际项目协议、核对字段与项目归属并取得相应授权；本地保存不等于接收成功。

## 停用与恢复

临时停用优先采用目标版本实际支持的技能配置。先让 Codex 找出当前配置文件和该技能绝对 `SKILL.md` 路径，提出具体修改与备份计划；获批后备份配置，将该技能的 `enabled` 设为 `false`，重启并验证不再加载。不要直接套用其他设备的绝对路径。

若目标版本不支持该配置，可提出将技能文件夹移到已指定、不会被发现的位置的替代方案；这是移动操作，必须另获明确批准后执行。不要自行删除。

恢复时先确认备份位置与同名冲突，提出恢复计划；获批后恢复配置或旧文件夹，重启并检查实际加载路径，再做一次只读调用。停用技能不会撤销此前已写入的项目文件、消息或聊天变更；这些对象需要分别按原记录处理。
