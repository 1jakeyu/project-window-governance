# 本地任务回执

`tasks.py receipt` 产生本地任务成果记录，并将同一回执关联到任务卡状态和交接。它不发送网络请求，也不直接声明与任意项目总控接收端兼容。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| receipt_id | 是 | 调用方提供的本项目、本任务、本轮稳定编号，单行且最多 200 字；同次重试保持不变 |
| task_id | 是 | 已存在的任务卡编号，如 T012 |
| occurred_at | 是 | 首次生成的带时区时间；同次重试保留 |
| task_status | 是 | 待启动 / 进行中 / 有阻塞 / 已暂停 / 待验收，遵守任务状态规则 |
| summary | 是 | 真实成果、差异和必要证据，最多 4000 字 |
| verification | 是 | unverified / passed / failed / mixed |
| checks | 是 | 列表，每项为 name、result、evidence；result 还可为 skipped |
| next_step | 是 | 明确下一步；确无下一步可为空字符串 |
| artifact_refs | 是 | 列表，每项为 device_id、path、description，只表示来源位置 |
| task_ref | 否 | 负责窗口标题；真实会话 ID 另在任务卡或既有台账关联 |

除 receipt_id 的更小限制外，每个字符串最多 4000 字，整份回执 UTF-8 不超过 64 KB。检查项的 passed 或 failed 必须附证据；总体 passed 必须至少有一项 passed，且其他项只能为 passed 或 skipped。检查通过不等于用户验收或项目完成；缺少验证时写 unverified。

## 生成、重试和恢复

```text
python <技能目录>/scripts/tasks.py --dir <现有任务卡目录> receipt <任务ID> --receipt-id <稳定编号> --status <任务状态> --summary <实际成果> --verification <验证结果> --next <下一步>
```

可重复传入 `--check "名称|结果|证据"` 和 `--artifact "路径|说明"`。`--window` 用于记录本轮负责窗口标题。命令中的尖括号代表需替换的实际内容；不要原样当成真实数据执行。

- 为同一轮确定一次编号，例如 `project-T012-round-001`；项目已有编号协议时沿用其稳定编号。脚本根据编号摘要生成文件名，原始编号保留在回执正文，不用用户输入直接拼接文件路径。
- 同 ID 同内容的重试复用原回执及时间，不重复追加交接；同 ID 不同内容必须报冲突。
- 已落盘回执不直接改写。需要更正时使用新编号，说明被更正的回执和原因。
- 写入中断后用 `recover --receipt-id <原编号>` 恢复同一次操作；发现外部修改等冲突时保留文件并停止写入，不通过删除日志或另换编号掩盖问题。
- 暂停、已完成或已取消任务不能被回执自动恢复。取得用户恢复决定后用 `resume <任务ID> --by-user`，重新检查验收标准后启动。
- 并发保护针对同一主机的本地文件写入，不提供跨设备或网络盘并发保证。默认最多等锁 8 秒；确需调整时可在子命令前传 `--lock-timeout 0` 至 `--lock-timeout 10`。锁和恢复记录由脚本管理，不擅自清理。

## 来源设备与外部对接

成果中的 `device_id` 来自所选任务目录的 `_config.json`、`TASK_DEVICE_ID` 或本机名称；这只是本地来源标记，不是受信设备认证。应核对其实际含义，不能把来源路径描述为已同步文件。

项目另有接收协议时先读取当前协议和受信配置。项目 ID、设备 ID、版本号、顺序号、字段白名单和大小限制都要按接收端核实；本地回执不能直接当成完整上报请求。真实上报要有对应授权、正确项目匹配和接收结果，保存本地文件不等于中央接收成功。

回执只保留完成任务所需的摘要和证据引用，不包含密码、API Key、Token、Cookie、凭证、完整聊天或无关私人信息。不为回执自动接入飞书、邮件、数据库或新的后台服务。
