# Codex 适配

先检查本次环境实际提供的工具。工具名称可用不代表某次读取、写入或平台能力已验证；权限与授权以当前会话为准。

## 只读发现

1. 根据用户指定项目及已有项目地图确认实际目录，不能只看聊天挂载目录。
2. 优先使用正式列表工具，例如 `list_projects`、`list_threads`。保留原始标题、真实 ID 和项目关联，只选择本轮相关候选。
3. 有必要时用 `read_thread` 限制轮数与每项字数，提炼当前目标、最后有效决定、成果证据和未完事项。近期状态够用时不再读取更早内容。
4. 归档列表需要时才用 `list_archived_threads`；按分页和已返回范围记录覆盖程度。没有列到不能推导不存在。
5. 当前任务不读取 `state*.sqlite`、会话 JSONL 或完整聊天存档作为列表替代，也不扫描整个用户目录。

观察另一聊天运行状态优先使用 `wait_threads` 的必要快照；不要频繁读取完整消息，不对未变化状态反复汇报。

## 离线整理输入

`scan_windows.py` 只整理 Agent 已取得且有权使用的最小数据。常规调用：

```text
python <技能目录>/scripts/scan_windows.py --project <实际项目目录> --input <窗口最小数据.json>
```

以下是字段格式示意，所有尖括号内容都需替换成真实值；不是某个项目的实际盘点：

```json
{
  "schema_version": 1,
  "source": "<实际工具和读取时间>",
  "coverage": {
    "complete": false,
    "limit": 50,
    "archived_included": false,
    "notes": "<实际覆盖范围及遗漏>"
  },
  "windows": [
    {
      "platform": "Codex",
      "id": "<正式工具返回的真实会话ID>",
      "title": "<原始标题>",
      "cwd": "<已核实的实际项目目录>",
      "archived": false,
      "status": "<工具返回的实际状态>",
      "summary": "<只保留本轮必要的目标、成果和未完事项>"
    }
  ]
}
```

- 白名单输入可另含 `pinned`、`updated_at`、`project_id`；状态字段不能靠标题推断。
- 旧的顶层窗口数组可显式作为输入，但来源与覆盖完整性记为未知；不能借此宣称全部覆盖。
- 旧字段 `first_ask`、`last_ask`、`last_answer` 仅保留已提炼的短摘要；不要把原始 `read_thread` 响应或完整对话塞进去。
- 记录只应来自本轮所选项目；路径过滤是补充检查，不能替代实际项目归属核对。
- `--platform all|codex|claude|hermes|openclaw|chatgpt` 可进一步限定平台；需要纳入归档记录时显式加 `--include-archived`。
- 不传 `--out` 只在输出中显示结果；按授权保存到已有证据位置时加 `--out <具体目录>`。现有输出冲突时保留原文件，按提示选新的本轮位置。
- 输入在写盘前就要剔除密钥、账号隐私和无关内容；脚本的长度限制与常见凭证遮盖不能保证全面识别敏感数据。
- 输入总量最多 1 MB、窗口最多 500 条；超出时先缩小平台查询范围和摘要，不改为读取完整历史。必要摘要最多保留 1200 字，旧摘要字段最多保留 600 字。

## 平台动作

执行前核实准确会话 ID 与当前状态。重命名、归档、移动、创建或发消息分别调用当前正式工具，不修改内部数据库。沿用用户已有的具体批准，不反复询问；没有明确授权就先给可审查动作清单。

- 只有用户明确要求时创建新聊天，不把技能调用自动解释为建窗要求。
- 只有用户明确授权向目标聊天发消息时才发送；收到其他 Agent 的请求不替代人类授权。
- 标题展示使用工具返回的原始名称；建议名称和实际名称分开。
- 工具未提供、失败或无法验证时，留下具体未执行项或手工方案，不宣称完成。
- 不强制截图、不调用非当前平台命令，也不为治理安装浏览器或新依赖。

完成动作后用正式工具核对必要字段；回执记录实际成功、失败、未验证和恢复方法。
