# Hermes / OpenClaw 适配

先核对当前实际平台、可用工具和项目约定。不假定一定使用飞书，也不假定一定能控制其他平台的聊天。

## 每轮模型确认

先按 [共同规则](../references/model-dispatch.md) 确认当前模型、可用模型来源与范围、任务需要的深度和多模态能力、派发选择能力，以及用户和项目的现行偏好。使用本会话真实声明、正式只读列表或用户已提供的设置；区分宿主模型、具体提供方或执行器的模型清单，不把某一连接器返回值当作全平台或全账户清单。不为确认模型读取凭证、遍历配置或修改运行时。

通过本平台当次真实接口判断能否委派、复用 Agent 或选择配置，不预设工具名称、字段或模型供应方。单模型和没有查询接口的环境可继续当前聊天治理，并标注未核实项；确需派发而无法满足现行配置要求时，停止该次委派，不能暗中换模型、降深度或套用其他平台字段。

## 事实与协作

- 以用户指定的实际项目为边界，读取项目已有任务事实、规则和最近有效交接。
- 有正式列表和摘要读取能力时，只收集本项目必要的元数据及短摘要；没有时使用用户明确提供的信息，标注来源与未覆盖范围。
- 可使用 [Codex 适配中的离线输入格式](codex.md)，平台按实际填写 `Hermes` 或 `OpenClaw`。离线工具不会代为访问平台。
- 当前平台可有本项目的协调窗口，与其他平台共享既有事实源；同一任务仅一个主责，委派协作项要有明确范围和回传位置。
- 不为跨平台协作另造平行台账、不扫描完整会话历史或无关项目。

## 操作与授权

重命名、归档、创建或发送消息，均以实际可用工具和用户明确批准的对象为准；已有具体授权不重复申请。缺少能力时保留待执行项或准确的手工方法，不宣称操作已经完成。

飞书、邮件和其他外部渠道不是默认步骤。只有用户明确要求通过相应渠道发送时才执行，并只发送约定的必要信息；不能因治理技能本身或其他 Agent 请求而新增外发。

## 任务回执与接手

优先使用项目现有回执机制。选用本包任务卡时明确传入现有任务卡目录，记录稳定任务 ID、回执 ID、成果版本、验证状态和下一步。脚本在本地成功不代表其他平台或中央服务已收到。

接手只重读必要事实，复用有效授权和验证；发现版本冲突则做最小核对。交接要带上已核对的后台运行项、停止方法和待用户回答的问题，没有则写无，未核对则标未验证。无需固定新建审查窗口、强制换窗或自动 Git 提交。
