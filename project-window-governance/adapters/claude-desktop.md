# Claude Desktop 适配

按当前环境实际提供的能力工作，不假定固定 MCP 服务、工具名称或界面控制接口一定存在。

## 每轮模型确认

先按 [共同规则](../references/model-dispatch.md) 核对当前模型的已知来源、用户或项目偏好、可用模型范围和选择能力。优先本会话真实声明、正式只读列表或用户已提供的设置；区分 Claude Desktop 当前聊天与某个 MCP 服务或外部执行器的模型，不能相互推导全部可用项。模型能力、思考深度或多模态支持没有证据时写未核实，不按品牌名称推定强弱。

只提供一个模型或没有模型查询接口时，可以继续当前聊天的治理，不强制用户切模型。需要委派时检查当前环境是否确实提供该能力以及平台自己的参数；不套用其他平台字段或把提示词当作配置。现行偏好要求的配置无法核实时停止该次委派，说明具体缺口，继续其他已授权工作。

## 收集本项目事实

- 先读用户指定项目的现有规则、任务台账和交接。
- 若环境提供正式聊天列表与读取工具，检查其能力后限定到本项目，取得原始标题、真实会话 ID、项目关联、状态和必要摘要。
- 列表不完整、缺少归档或无法确定项目归属时，明确范围；只请求会改变治理结论的缺失信息。
- 无正式读取工具时，使用用户已经提供的窗口清单或摘要。无法取得的状态写未验证，不转读私有数据库、整段日志或扫描用户目录。
- 最小窗口数据可按 [Codex 适配中的输入格式](codex.md) 交给离线扫描器，平台填 `Claude`；来源填写真实工具或用户提供，不伪装成接口核对。

## 责任和动作

Claude 可设本项目协调窗口，与其他平台共用项目现有事实源；同一任务仅一个当前主责。无需再新建一套任务目录或强制迁移已有命名。

需要改名、归档、创建、移动或发消息时，先确定具体对象、影响、恢复办法与用户授权，再使用当前环境确实支持的正式工具。用户已给出的具体批准可复用，不重复询问。

未提供相应能力时，给出准确的手工操作清单；清楚记录“待用户操作”，不把建议写成实际执行。不得虚构工具名称、调用结果或会话 ID。

## 交接

使用项目既有交接位置，保留目标、有效决定、成果版本与路径、验证、剩余、授权和下一步。跨平台接手使用任务 ID 和成果引用关联；来源路径不等于文件已同步，不复制完整聊天或凭证。
