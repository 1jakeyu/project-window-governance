# 项目窗口与任务治理

**让项目的聊天、任务、主责和验证证据对得上。**

`project-window-governance` 是面向 Codex 的治理技能：帮助你盘点指定项目的聊天职责、发现重复派工和状态冲突、维护任务回执，并在换窗时留下能继续执行的交接。

你可以直接在单个项目聊天中使用。需要集中查看多个项目时，也可以选择一个总控入口逐项目调用，各项目继续保留原有执行聊天与记录。

**当前为公开发布候选 `pwg-public-20261109-rc1`。** 十二个技能文件来自安装记录标识为 `2026.10.13.1` 的快照，按字节保留；历史正式维护源尚未确认。此次建立独立仓库用于版本管理与后续维护，不把安装目录当作开发源。

## 它能帮助你做什么

| 遇到的问题 | 技能提供的工作 |
|---|---|
| 多个聊天都在处理同一项任务 | 对照任务与成果证据，明确当前唯一主责和协作范围 |
| 聊天说完成，文件或检查结果对不上 | 区分摘要宣称、实际成果、程序验证和用户验收 |
| 想集中看几个项目的进度 | 在一个入口逐项目整理最少必要摘要，沿用各项目事实源 |
| 要换聊天或交接到其他设备 | 保留有效决定、成果位置、验证限制、剩余任务和下一步 |
| 需要稳定的本地任务记录 | 在项目选择该格式并获写入授权后，用辅助脚本维护任务卡及可恢复回执 |

技能提供方法和离线辅助脚本。读取或操作其他聊天仍依赖目标环境的正式工具与具体授权；缺少工具时，可由用户传递最小摘要。它不会自动常驻、跨设备调度、建立聊天或连接中央服务。

## 第一次试用：只读盘点

安装完成后，在你选定的项目聊天中发送下面这段。先把尖括号替换成目标设备的实际信息；未知的项目入口写“未知”。

```text
$project-window-governance
本轮只读盘点：<项目名称>，实际目录：<真实项目路径>。
已有规则、任务台账和交接入口：<准确位置；未知写未知>。
请先确认技能加载位置、项目归属和可用工具，只读取本项目必要资料。
列出任务、当前唯一主责、成果与验证证据、冲突及下一步。
工具或资料未覆盖的部分明确写未验证。
本轮不写文件、不发送消息、不新建或改名归档聊天。
需要后续操作时，先列准确对象、影响和恢复办法。
```

预期结果是一份有来源、覆盖范围和下一步的项目盘点。没有实际检查的内容应标为未验证，不应凭聊天标题推断项目完成。

## 安装要点

1. 将版本 ZIP 解压到新文件夹，先看中文安装说明。
2. 让目标 Codex 确认它实际读取的技能目录，再复制整个 `project-window-governance` 文件夹。
3. 安装后应直接得到 `<已确认的技能目录>/project-window-governance/SKILL.md`，不要嵌套两层同名文件夹。
4. 遇到已有同名技能，先比较文件并提出备份与替换计划；获批后再替换，不合并覆盖。
5. 用上面的只读提示词确认实际加载路径。路径不对、重复加载或无法发现时，先停止安装变更并保留现状。

本仓库根包含交付说明，真正需要复制的技能在子目录 `project-window-governance/`。安装不会把旧设备的批准转移到新设备。

## 依赖与兼容性

| 使用方式 | 需要什么 | 本候选验证情况 |
|---|---|---|
| 阅读技能、整理已有资料 | 能加载技能的目标 Codex；已获准的项目资料 | 已进行合成请求演练；目标设备发现待验证 |
| 读取或操作其他聊天 | 目标环境提供的正式列表、读取和相应操作工具 | 实际能力按当前环境核对；没有工具可手动传递摘要 |
| 两个离线辅助脚本 | Python 标准库；最低 Python 3.9 为静态推断 | Windows Python 3.12.10 实测；Python 3.9 实机未验证 |
| Mac 上运行辅助脚本 | 目标设备已有合适 Python | 已做静态检查；Mac 实机及锁并发未验证 |

只有运行 `scan_windows.py`、`tasks.py` 才需要 Python。阅读与使用技能说明不要求安装 Python，也不要求 API Key。

## 验证与使用边界

原技能字节保持一致，沿用本轮已经实际完成的 Windows 离线验证：**23 项通过、0 项失败、4 项未验证**。覆盖项目过滤、输出冲突保护、任务草稿约束、回执去重、状态恢复、三个写入中断边界和同机锁。中断使用异常注入，未模拟真实断电。

尚未验证：Mac 实机、Python 3.9 实机、符号链接/联接点权限、真实断电或杀进程、跨设备或网络盘并发、真实聊天操作、真实项目试点。格式检查器因缺少 PyYAML 未能运行，已用标准库检查现有简单字段和引用；不宣称官方检查器通过。

核心规则：最小读取、同一任务只有一个当前主责、真实验证、稳定回执编号、冲突时停止写入、明确的操作授权。没有获准的动作保留为建议；程序检查通过不等于用户验收。跨设备共享目录仍保持单一写入主责。

## 一个总控入口，怎样逐项目使用

总控先读取用户指定项目的最小摘要，再选定一个项目调用技能。治理结论回到该项目已有记录；同一任务保持稳定编号和唯一主责。下一个项目重复这一过程，不混用目录、任务状态或操作授权。

包内有完全合成的“三个项目、五项任务”例子。真实试点可由用户选三个活跃项目、至少五项任务，运行五至十个工作日；例子、安装成功或时间到期都不能替代试点证据。
