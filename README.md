## 自动安装

**复制下面这段话，发给你正在使用的智能体。**由它核对当前平台并自动获取技能，你无需自己下载、解压或输入命令：

```text
请安装这个窗口治理技能：
https://github.com/1jakeyu/project-window-governance/tree/pwg-public-20261109-rc3/project-window-governance

先确认当前平台支持本地 Skill，以及实际安装和加载目录。
如有同名版本，先列出差异、备份位置和恢复办法，等我确认再更新。
只安装这一项，其他技能不要动。
完成后报告来源版本、安装路径、文件完整性和实际加载结果；未验证的项目明确标注。
```

Codex 用户也可发送下面的快捷指令，调用内置安装器：

```text
$skill-installer https://github.com/1jakeyu/project-window-governance/tree/pwg-public-20261109-rc3/project-window-governance
```

当前安装目标为固定候选 **`pwg-public-20261109-rc3`**。本次只更新仓库首页和图片，不更改该版本的下载包；已安装 rc3 的用户无需重复安装。

“自动安装”由智能体执行，仍遵守当前平台的权限要求。Codex 的固定版本获取与本机更新已有实际验证；其他平台先确认技能格式、发现目录和获取工具。若不支持技能加载，只能将说明作为工作指南，不能报告为安装成功。Codex 安装方式见[官方说明](https://learn.chatgpt.com/docs/build-skills)。

需要手动或离线安装时，再看 [安装与恢复说明](docs/安装与使用.md) 和 [候选版附件](https://github.com/1jakeyu/project-window-governance/releases/tag/pwg-public-20261109-rc3)。ZIP 是备用入口。

## 安装确认

安装后，再把下面这段话发给智能体。**只说“下载成功”，还不能确认已经加载。**

```text
请只读核验 project-window-governance 的安装，不改文件或聊天：
1. 报告实际安装目录和本次加载的 SKILL.md 绝对路径，确认没有多套一层同名目录。
2. 核对来源为 pwg-public-20261109-rc3；按该版本 FILES.json 中技能子目录的 13 个文件逐一核对指纹，并单独说明本机附加记录。
3. 使用当前平台支持的方式调用技能，确认能够读取入口、适配文件和 references/model-dispatch.md。
4. 简述“先确认平台、模型来源和工具能力”的规则；说明单模型或无查询接口时如何继续当前聊天的治理。
分别报告已验证通过、失败、未验证。缺少来源或加载证据时不要猜测版本或宣称成功。
```

指纹是用于比较文件内容的校验值，由智能体核对即可。安装核验使用固定版本的 [FILES.json](https://github.com/1jakeyu/project-window-governance/blob/pwg-public-20261109-rc3/FILES.json)，而不是凭文件夹名称判断版本。

| 检查项 | 应看到的结果 |
|---|---|
| 版本内容 | 明确对应 `pwg-public-20261109-rc3`，有来源记录或与固定清单一致的文件核对证据；仅凭指纹一致不证明下载来源 |
| 安装与加载路径 | 指向当前平台实际发现的技能目录，入口直接为 `project-window-governance/SKILL.md` |
| 文件完整性 | 该版本的 13 个技能文件逐一核对一致，入口和相关引用可读 |
| 实际调用 | 按当前平台方式找到并调用技能，能说明模型确认规则；仅直接读文件时，加载仍记为未验证 |

若 Codex 尚未发现新技能，重启后再试一次；其他平台按其实际刷新方式处理。路径不对、存在两份同名、文件不一致或仍不能加载时，**停止后续写操作，保留现状和备份**，先核对指定目录，不反复覆盖。

## 开始使用

安装确认后，在准备治理的项目聊天里发送下面这段话。将 `<项目名称>` 和 `<项目路径>` 换成自己的信息：

```text
请使用 project-window-governance，只读盘点我的 <项目名称>。
实际项目目录是 <项目路径>。
先核对当前平台、可用模型及工具能力，说明信息来源和未核实部分。
沿用已有规则、任务记录和交接，列出任务、唯一主责、验证证据、冲突和下一步。
本轮不写文件、不发送消息，也不创建、改名或归档聊天。
```

第一次应得到一份可核对的盘点结果：任务在做什么、谁负责、成果在哪里、哪些已验证、还有什么冲突及下一步；证据不足的内容明确标注。先检查盘点是否准确，再批准具体的整理、派发或归档清单。

在 Codex 中也可用 `$project-window-governance` 明确调用。其他平台使用其实际支持的调用方式。更多例子见[提示词与试点](docs/提示词与试点.md)。

## 它解决什么

| 常见情况 | 期望得到的结果 |
|---|---|
| 多个聊天在做同一项任务 | 对照证据，明确当前唯一主责与协作范围 |
| 聊天说完成，成果或检查对不上 | 区分实际成果、程序检查和用户验收 |
| 想查看多个项目的进度 | 在一个总控入口逐项目复用已有记录 |
| 需要换聊天或交接 | 留下决定、成果位置、验证限制和下一步 |

从一个项目开始，先核对来源和实际覆盖范围；发现冲突先补查证据。缺少跨聊天工具时，可由用户手动传递最小摘要。稳定回执编号供同次重试使用，一轮聊天结束不等于项目完成。

## 模型选择

**每轮治理先确认当前环境有什么模型，再讨论用哪个。**依据本会话正式工具声明、可用的只读模型列表或用户提供的设置核对；注明来源、已确认范围、思考深度和任务派发能力。只能看到部分模型时，不把它当作完整账号清单。

公开规则不固定平台、模型品牌或思考档位。先遵守当地使用者的明确偏好，再按任务难点、输入类型及实际可用能力选择；参数按目标平台的真实接口传入，不能把模型名写在提示词里就说已经切换。

只有一个模型，或没有查询/切换接口时，仍可在当前聊天完成不依赖切换的治理；未核实的信息如实标注。委派所需模型或参数不可用时，停止该次委派并说明限制，不静默替换。复用及继续委派同样检查。详见[模型与派发规则](project-window-governance/references/model-dispatch.md)。

## 验证与边界

- **此次首页更新：**采用 VI 封面和两张流程图 v2，补齐自动安装、安装确认与首次只读使用；技能规则、辅助脚本和 rc3 发布附件保持原样。
- **rc3 已有改动：**通用平台与模型确认规则、各平台适配、README 自动安装入口；合并原“先读我”和“验证摘要”。
- **历史脚本结果：**Windows / Python 3.12.10 合成数据检查为 23 项通过、0 项失败、4 项未验证。本候选未重跑这 23 项；涵盖项目过滤、草稿验收、稳定回执、写入中断恢复和同机锁，异常注入不等于真实断电。
- **rc3 发布时检查：**核对最终规则与平台边界、引用、文件清单和来源差异，检查两个脚本语法与命令入口，并核对 ZIP 解压后的文件指纹。具体记录随本候选发布说明提供。
- **仍未验证：**Mac、Python 3.9 实机、真实跨聊天操作、跨设备或网络盘并发、真实项目试点，以及未在本机测试的其他平台。支持通用方法不等于所有平台都已实测。
- **格式检查：**使用本机另一套已有 Python 环境原样运行官方 `quick_validate.py`，检查通过；没有安装或升级依赖。格式通过不等于平台行为已验证。

技能提供工作方法和可选离线工具，不授予操作权限，不常驻后台，也不自动跨设备同步。正式平台工具和具体授权决定能执行什么；程序检查通过与用户验收分别记录。

来源基线为安装记录标识 `2026.10.13.1` 的历史快照。当前仓库维护公开候选，历史维护源的优先关系仍未确认。原文件指纹、明确改动和当前仓库文件清单见 [PACKAGE.json](PACKAGE.json) 与 [FILES.json](FILES.json)；固定 rc3 下载包以该发布版本的清单为准。旧图标与旧发布版本保留。指纹用于核对内容，不是身份签名。

## 依赖与兼容性

| 使用方式 | 需要什么 |
|---|---|
| 阅读规则、整理已有资料 | 能读取技能说明的智能体，以及已获准的项目资料 |
| 正式技能加载 | 当前平台支持的 Skill 格式和实际发现目录 |
| 读取或操作其他聊天 | 当前环境实际提供的正式工具与具体授权 |
| 可选离线辅助脚本 | 已有 Python 标准库；最低 Python 3.9 为静态推断，实测为 Windows Python 3.12.10 |

只有运行 `scan_windows.py` 或 `tasks.py` 才需要 Python。阅读规则不要求安装 Python 或提供 API Key；外部平台工具的要求由该平台自行核对。
